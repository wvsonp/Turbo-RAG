# 1.10 Workload Identity bindings

## Goal

Each service pod authenticates to GCP APIs via Kubernetes Service Account → GCP Service Account binding—**no JSON keys in containers**.

## Scope

- `infra/modules/iam/` — GCP SAs per service
- `google_service_account_iam_member` workloadIdentityUser bindings
- Helm ServiceAccount annotations

## Prerequisites

- [1.3 GKE](1.3-gke-cluster.md) with Workload Identity enabled
- [1.8 Helm](1.8-helm-charts.md) ServiceAccount templates

## Implementation notes

Terraform:

```hcl
resource "google_service_account_iam_member" "workload_identity" {
  service_account_id = google_service_account.api.name
  role               = "roles/iam.workloadIdentityUser"
  member             = "serviceAccount:${var.project_id}.svc.id.goog[${var.namespace}/${var.ksa_name}]"
}
```

Kubernetes:

```yaml
metadata:
  annotations:
    iam.gke.io/gcp-service-account: api-sa@turbo-rag.iam.gserviceaccount.com
```

Grant **least privilege** per SA, e.g.:

| Service | Example roles |
| ------- | ------------- |
| api | `secretmanager.secretAccessor`, `cloudsql.client` |
| workers | `storage.objectViewer`, `aiplatform.user`, Pub/Sub subscriber |
| ingestion | GCS + Pub/Sub publish/subscribe as needed |

## Acceptance criteria

- [ ] GCP SA + WI binding exists per service in Terraform.
- [ ] Helm-deployed pods use annotated Kubernetes SA.
- [ ] Proof call from pod: list GCS bucket or access Secret Manager without mounted key file.
- [ ] No `GOOGLE_APPLICATION_CREDENTIALS` pointing to JSON in Deployment manifests.

## Validation commands

```bash
kubectl run -it --rm wi-test --image=google/cloud-sdk:slim \
  --serviceaccount=api -n platform -- \
  gcloud storage ls gs://<test-bucket>/
```

## Rollback / cleanup

- Remove IAM bindings before deleting GCP SAs.

## Production notes

- Separate GCP SAs per environment; no cross-env binding.
