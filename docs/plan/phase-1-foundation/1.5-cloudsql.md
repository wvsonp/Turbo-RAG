# 1.5 Cloud SQL (PostgreSQL)

## Goal

Managed PostgreSQL with **private IP**, **IAM database authentication**, automated backups, and databases for platform metadata.

## Scope

- `infra/modules/cloudsql/`
- PostgreSQL 15
- Databases: `rag_metadata`, `langfuse`, `mlflow`

## Prerequisites

- [1.2b Network foundation](1.2b-network-foundation.md) (PSA connection)
- API `sqladmin.googleapis.com`

## Implementation notes

| Setting | Dev | Prod |
| ------- | --- | ---- |
| Tier | `db-f1-micro` | `db-g1-small` or higher |
| Public IP | disabled | disabled |
| IAM auth | enabled | enabled |
| Backups | on, 7-day retention minimum | on, PITR enabled |
| HA | optional (Zonal OK for dev) | Regional HA recommended |

Connect from GKE via private IP + Workload Identity DB auth (users mapped to GCP SA emails).

## Acceptance criteria

- [ ] Instance provisioned via Terraform with private IP only.
- [ ] PSA peering in use; no `0.0.0.0/0` authorized networks.
- [ ] Automated backups enabled; PITR documented for prod tfvars.
- [ ] Three databases created.
- [ ] Test connection from a debug pod or Cloud SQL Auth Proxy documented in `docs/history/cloudsql.md`.

## Validation commands

```bash
cd infra && terraform plan -var-file=environments/dev.tfvars -target=module.cloudsql
gcloud sql instances describe <instance-name> --project=turbo-rag
gcloud sql databases list --instance=<instance-name>
```

## Rollback / cleanup

- Export if needed before `terraform destroy -target=module.cloudsql`.

## Production notes

- Maintenance window defined; deletion protection enabled on prod instance.
- Store instance connection name in Terraform outputs for Helm values.
