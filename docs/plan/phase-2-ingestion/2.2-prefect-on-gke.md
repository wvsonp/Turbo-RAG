# 2.2 Prefect on GKE

## Goal

Prefect 2.x server and workers run on GKE: server on the **system** node pool, flow execution on the **worker** (Spot) pool. Orchestrator uses the `prefect` PostgreSQL database on Cloud SQL. GCS / Pub/Sub / Vertex access for flows is already granted in [2.1](2.1-gcs-pubsub.md) — not repeated here.

## Scope

### Cloud SQL

Add `prefect` to `local.databases` in [`infra/modules/cloudsql/main.tf`](../../../infra/modules/cloudsql/main.tf) (same `google_sql_database.platform` `for_each` — DRY).

Apply with targeted Cloud SQL module or full apply; verify:

```bash
terraform output cloudsql_database_names | grep prefect
```

Prefect server connection string uses private IP + IAM auth via `workers-sa-{env}` (or dedicated prefect SA if split later).

### Helm — Prefect 2.x

- Chart: official Prefect Helm chart or maintained fork (document chosen chart in `docs/history/` on completion).
- Namespace: `prefect` (create via Helm `--create-namespace`).
- **Server / API:** `nodeSelector` → `cloud.google.com/gke-nodepool: system` (stable pool).
- **Workers / agents:** `nodeSelector` → `cloud.google.com/gke-nodepool: worker` plus Spot tolerations if required by chart defaults.
- Work pool / work queue aligned with Kubernetes job execution (Prefect `kubernetes` work pool type).

**Install options:**

1. **Helm** (preferred) — requires `helm` on PATH.
2. **kubectl fallback** — if `helm` missing locally, document equivalent manifests in `docs/history/` (same pattern as Secret Manager CSI in Phase 1 — see [`docs/FAILURES.md`](../../FAILURES.md) “Helm not installed”).

**Not in scope:** Qdrant IAM (cluster-internal HTTP only). WI for GCS / Vertex / Pub/Sub belongs in [2.1](2.1-gcs-pubsub.md).

### Tool prerequisites

`kubectl`, `gke-gcloud-auth-plugin`, and `helm` (or kubectl fallback) per [Phase 2 README](README.md#before-you-start).

## Prerequisites

- [2.1](2.1-gcs-pubsub.md) — Pub/Sub path and ingestion/workers IAM
- Phase 1 GKE pools ([1.3](../phase-1-foundation/1.3-gke-cluster.md)) — `system` and `worker` pools Ready
- At least one **worker** pool node Ready before flow job validation

## Implementation notes

```yaml
# Example nodeSelector for Prefect server deployment
nodeSelector:
  cloud.google.com/gke-nodepool: system
```

```yaml
# Example for flow worker / job template
nodeSelector:
  cloud.google.com/gke-nodepool: worker
tolerations:
  - key: cloud.google.com/gke-spot
    operator: Equal
    value: "true"
    effect: NoSchedule
```

Ensure Prefect metadata PVC (if any) uses writable paths under the mount (see Qdrant snapshot lesson in [`docs/history/lessons.md`](../../history/lessons.md)).

## Acceptance criteria

- [ ] `prefect` database listed in `terraform output cloudsql_database_names`.
- [ ] Prefect server pod Ready on **system** pool (`kubectl get pods -n prefect -o wide`).
- [ ] Prefect UI or API reachable inside cluster (ingress optional for dev).
- [ ] Sample flow runs successfully as a Kubernetes job on **worker** pool.
- [ ] Flow run logs visible in Prefect UI.
- [ ] Prefect server connects to Cloud SQL using IAM database auth (workers or server GSA with `cloudsql.client` + IAM user from 1.10).

## Validation commands

```bash
gcloud container clusters get-credentials rag-platform-dev --region us-central1 --project turbo-rag

kubectl get nodes -L cloud.google.com/gke-nodepool
kubectl get pods -n prefect -o wide

# After helm upgrade --install prefect ...
prefect deployment run hello-flow   # or equivalent from operator pod
kubectl get jobs -n prefect
```

## Rollback / cleanup

- `helm uninstall prefect -n prefect` before removing `prefect` database (drop DB only when no server references it).

## Production notes

- Run server on non-Spot pool in all environments; size worker pool for peak embedding concurrency.
