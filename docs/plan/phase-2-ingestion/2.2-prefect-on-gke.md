# 2.2 Prefect on GKE

## Goal

Prefect 2.x server and workers run on GKE: server on the **system** node pool, flow execution on the **worker** (Spot) pool. Orchestrator uses the `prefect` PostgreSQL database on Cloud SQL with explicit IAM auth. Service identities for Prefect server and flow jobs are defined here so Cloud SQL and GCP API access work without JSON keys.

## Scope

### Cloud SQL

Add `prefect` to `local.databases` in [`infra/modules/cloudsql/main.tf`](../../../infra/modules/cloudsql/main.tf) (same `google_sql_database.platform` `for_each` — DRY).

Apply with targeted Cloud SQL module or full apply; verify:

```bash
terraform output cloudsql_database_names | grep prefect
```

### Service identities (Terraform — `infra/modules/iam/`)

Add to Phase 1.10 pattern (DRY `local.services` or dedicated block):

| Component | K8s namespace | KSA | GCP SA | IAM roles | Cloud SQL IAM user |
| --------- | ------------- | --- | ------ | --------- | ------------------ |
| Prefect server | `prefect` | `prefect-server` | `prefect-server-sa-{env}` | `roles/cloudsql.client` | `prefect` database |
| Prefect flow jobs | `prefect` | `workers` | `workers-sa-{env}` (reuse) | `roles/cloudsql.client`, `roles/storage.objectViewer`, `roles/aiplatform.user` | `rag_metadata` database |
| Dispatcher | `platform` | `ingestion` | `ingestion-sa-{env}` | See [2.1](2.1-gcs-pubsub.md) | — |

**Workload Identity bindings:**

```hcl
# prefect-server-sa-{env} ← prefect/prefect-server
member = "serviceAccount:${var.project_id}.svc.id.goog[prefect/prefect-server]"

# workers-sa-{env} ← prefect/workers (flow job template)
member = "serviceAccount:${var.project_id}.svc.id.goog[prefect/workers]"
```

**Cloud SQL connection (both Prefect server and flow jobs):**

- Private IP only (from [1.5](../phase-1-foundation/1.5-cloudsql.md))
- Cloud SQL Auth Proxy sidecar or Python connector with IAM auth
- Connection string pattern: `postgresql+asyncpg://<gsa-email>@/<db>?host=/cloudsql/<connection-name>` (adjust for chosen connector)
- **No** `postgres` password in Kubernetes Secrets for Phase 2 dev

Document chosen connector and Helm values in `docs/history/` on completion.

### Helm — Prefect 2.x

- Chart: official Prefect Helm chart or maintained fork (document chosen chart in `docs/history/` on completion).
- Namespace: `prefect` (create via Helm `--create-namespace`).
- **Server / API:** `nodeSelector` → `cloud.google.com/gke-nodepool: system` (stable pool).
- **Server ServiceAccount:** `prefect-server` with annotation `iam.gke.io/gcp-service-account: prefect-server-sa-{env}@...`
- **Workers / agents:** `nodeSelector` → `cloud.google.com/gke-nodepool: worker` plus Spot tolerations if required by chart defaults.
- **Flow job template ServiceAccount:** `workers` with annotation `iam.gke.io/gcp-service-account: workers-sa-{env}@...`
- Work pool / work queue aligned with Kubernetes job execution (Prefect `kubernetes` work pool type).

**Install options:**

1. **Helm** (preferred) — requires `helm` on PATH.
2. **kubectl fallback** — if `helm` missing locally, document equivalent manifests in `docs/history/` (same pattern as Secret Manager CSI in Phase 1 — see [`docs/FAILURES.md`](../../FAILURES.md) “Helm not installed”).

**Not in scope:** Qdrant IAM (cluster-internal HTTP only). Pub/Sub subscriber for main sub belongs to dispatcher ([2.1](2.1-gcs-pubsub.md)), not Prefect server.

### Tool prerequisites

`kubectl`, `gke-gcloud-auth-plugin`, and `helm` (or kubectl fallback) per [Phase 2 README](README.md#before-you-start).

## Implementation notes

```yaml
# Prefect server deployment
nodeSelector:
  cloud.google.com/gke-nodepool: system
serviceAccount:
  name: prefect-server
  annotations:
    iam.gke.io/gcp-service-account: prefect-server-sa-dev@turbo-rag.iam.gserviceaccount.com
```

```yaml
# Flow worker / job template
nodeSelector:
  cloud.google.com/gke-nodepool: worker
tolerations:
  - key: cloud.google.com/gke-spot
    operator: Equal
    value: "true"
    effect: NoSchedule
serviceAccount:
  name: workers
  annotations:
    iam.gke.io/gcp-service-account: workers-sa-dev@turbo-rag.iam.gserviceaccount.com
```

Ensure Prefect metadata PVC (if any) uses writable paths under the mount (see Qdrant snapshot lesson in [`docs/history/lessons.md`](../../history/lessons.md)).

## Acceptance criteria

- [ ] `prefect` database listed in `terraform output cloudsql_database_names`.
- [ ] `prefect-server-sa-{env}` GCP SA + WI binding to `prefect/prefect-server` in Terraform.
- [ ] `workers-sa-{env}` WI binding includes `prefect/workers` (in addition to `platform/workers` if both exist).
- [ ] Cloud SQL IAM users created for `prefect-server-sa-{env}` and `workers-sa-{env}`.
- [ ] Prefect server pod Ready on **system** pool (`kubectl get pods -n prefect -o wide`).
- [ ] Prefect UI or API reachable inside cluster (ingress optional for dev).
- [ ] Sample flow runs successfully as a Kubernetes job on **worker** pool.
- [ ] Flow run logs visible in Prefect UI.
- [ ] Prefect server connects to Cloud SQL `prefect` DB using IAM auth (no password secret).
- [ ] Sample flow job can connect to Cloud SQL `rag_metadata` using IAM auth.

## Validation commands

```bash
gcloud container clusters get-credentials rag-platform-dev --region us-central1 --project turbo-rag

kubectl get nodes -L cloud.google.com/gke-nodepool
kubectl get pods -n prefect -o wide
kubectl get sa -n prefect prefect-server workers \
  -o custom-columns=NAME:.metadata.name,GSA:.metadata.annotations.'iam\.gke\.io/gcp-service-account'

# WI proof for prefect-server
kubectl run wi-prefect-server --rm -i --restart=Never -n prefect \
  --image=curlimages/curl:latest \
  --overrides='{"spec":{"serviceAccountName":"prefect-server"}}' \
  -- curl -sf -H "Metadata-Flavor: Google" \
  "http://metadata.google.internal/computeMetadata/v1/instance/service-accounts/default/email"

# After helm upgrade --install prefect ...
prefect deployment run hello-flow   # or equivalent from operator pod
kubectl get jobs -n prefect
```

## Rollback / cleanup

- `helm uninstall prefect -n prefect` before removing `prefect` database (drop DB only when no server references it).
- Remove WI bindings for `prefect/*` KSAs before deleting GCP SAs.

## Production notes

- Run server on non-Spot pool in all environments; size worker pool for peak embedding concurrency.
- Dedicated `prefect-server-sa` per environment; no cross-env WI binding.
