# 2.3 Ingestion flow (parse → chunk → embed → upsert)

## Goal

End-to-end ingestion triggered by the **dispatcher** ([2.1](2.1-gcs-pubsub.md)): Prefect flow reads GCS object by `bucket + name + generation` → parse → chunk → embed (Vertex `text-embedding-004`) → Qdrant upsert → PostgreSQL metadata in `rag_metadata`. Design for idempotency, stale chunk cleanup, batching, and clear retry boundaries.

## Scope

### Components

| Component | Location | Responsibility |
| --------- | -------- | -------------- |
| Dispatcher | `services/ingestion/` (or dedicated package) | Pub/Sub pull, start Prefect run, ack/nack |
| Ingestion flow | `services/workers/` flows package | Parse, chunk, embed, upsert, metadata |
| Shared contracts | `services/workers/` or `libs/` | Document IDs, chunk IDs, Qdrant schema, config |

### Document identity

| Field | Definition |
| ----- | ---------- |
| `logical_uri` | `gs://{bucket}/{object_name}` — stable across overwrites |
| `document_version_id` | `{bucket}/{object_name}#{generation}` — canonical version key |
| `content_hash` | SHA-256 of object bytes — stored for audit; not primary id |

On each flow run, read object metadata from GCS to confirm `generation` matches the Pub/Sub payload before processing.

### Metadata schema (`rag_metadata`)

Create via migration (Alembic or equivalent) before flow validation:

| Table | Purpose | Key constraints |
| ----- | ------- | --------------- |
| `documents` | Logical document | `UNIQUE(logical_uri)`; `latest_version_id` FK |
| `document_versions` | Immutable version per GCS generation | `UNIQUE(bucket, object_name, generation)` |
| `chunks` | Chunk records per version | `UNIQUE(document_version_id, chunk_index)` |
| `ingestion_runs` | Audit trail | `UNIQUE(prefect_flow_run_id)` |

**Status values:** `pending` → `processing` → `completed` | `failed`

### Qdrant conventions

| Setting | Value |
| ------- | ----- |
| Collection name | From config (e.g. `rag_chunks_dev`) — single source in values/env |
| Vector size | Match `text-embedding-004` output dimension |
| Distance | Cosine |

**Point ID:** `uuid5(NAMESPACE_DOCUMENT, f"{bucket}/{object_name}#{generation}:{chunk_index}")`

**Payload (minimum):** `logical_uri`, `document_version_id`, `chunk_index`, `generation`, `content_hash`, `source_uri`, `text_preview` (truncated)

### Idempotency and stale cleanup

1. **Upsert by version:** Re-running the same `(bucket, object_name, generation)` updates existing rows and Qdrant points; point count for that version unchanged.
2. **New generation:** When `generation` increases for the same `logical_uri`:
   - Mark previous `document_versions.status = superseded`
   - Update `documents.latest_version_id`
   - Delete Qdrant points where `document_version_id` matches superseded version(s)
   - Delete or mark inactive `chunks` for superseded version
3. **Shrinking documents:** If new version has fewer chunks, delete Qdrant points and DB rows for chunk indices ≥ new chunk count on that version.
4. **Partial failure:** Metadata transaction commits before Qdrant upsert; on Qdrant failure, set `ingestion_runs.status = failed` and leave version `processing` or `failed` for retry. Retry must be safe (same point IDs).

### Flow steps (Prefect)

1. Validate inputs: `bucket`, `object_name`, `generation`.
2. Download object from GCS (streaming for large files).
3. Parse document (PDF/text); enforce dev size limit (e.g. 10-page PDF, max 10 MB — config).
4. Chunk using default chunker (from config; experiments in [2.4](2.4-chunking-mlflow.md)).
5. Batch embed via Vertex (`text-embedding-004`, region from config).
6. **DB transaction:** upsert `documents`, `document_versions`, `chunks`, `ingestion_runs`.
7. Batch upsert Qdrant points.
8. Run stale cleanup for superseded versions of same `logical_uri`.
9. Set `document_versions.status = completed`, `ingestion_runs.status = completed`.

### Performance

| Parameter | Dev default | Notes |
| --------- | ----------- | ----- |
| Embedding batch size | 32 texts | Tune to Vertex quota; config-driven |
| Qdrant upsert batch size | 100 points | Use batch API |
| Max concurrent flow runs | 2 | Dispatcher config; avoid Spot preemption storms |
| Vertex retry | 3 attempts, exponential backoff (1s, 4s, 16s) | Transient errors only |
| Qdrant / Cloud SQL retry | 3 attempts, same backoff | Idempotent ops only |

### Dispatcher ↔ Prefect contract

Dispatcher passes flow parameters:

```json
{
  "bucket": "rag-ingestion-dev",
  "object_name": "incoming/sample.pdf",
  "generation": "1234567890",
  "pubsub_message_id": "..."
}
```

Dispatcher behavior:

- **Ack** Pub/Sub message when Prefect flow run state = `Completed`.
- **Nack** (modify ack deadline to 0 or do not extend) when state = `Failed` / `Cancelled` / timeout.
- Extend ack deadline every N seconds while flow is `Running`.
- Skip duplicate in-flight runs for same `document_version_id`.

### Secrets and config

- Vertex model, region, batch sizes: single config module / Helm values — not hardcoded in multiple files.
- OpenAI API key (dev tests only): `/var/secrets/openai-api-key` via Secret Manager CSI ([1.6](../phase-1-foundation/1.6-secret-manager.md)) — **not** `OPENAI_API_KEY` env var in Deployment manifests.

**Out of scope:** DLQ Terraform ([2.5](2.5-dlq-idempotency.md)); chunking strategy comparison ([2.4](2.4-chunking-mlflow.md)).

## Acceptance criteria

- [ ] Dispatcher deployed; pulls from `ingestion-uploads-sub` without early ack.
- [ ] Upload triggers dispatcher → Prefect flow run with correct `bucket`, `object_name`, `generation`.
- [ ] Single PDF/text upload results in searchable vectors in Qdrant.
- [ ] Metadata rows exist in `documents`, `document_versions`, `chunks`, `ingestion_runs`.
- [ ] Flow retries transient Vertex/Qdrant/Cloud SQL errors with backoff.
- [ ] End-to-end run completes in dev under documented size limit (e.g. 10-page PDF).
- [ ] Re-running same `(bucket, object_name, generation)` yields same Qdrant point IDs; point count for that version unchanged.
- [ ] Uploading new generation of same object supersedes old version; old Qdrant points removed.
- [ ] Structured logs include `document_version_id`, `prefect_flow_run_id`, `pubsub_message_id`.

## Validation commands

```bash
# Upload trigger (see 2.1 — do not auto-ack main sub manually)
echo test > /tmp/sample.txt
gcloud storage cp /tmp/sample.txt gs://<ingestion-bucket>/incoming/sample.txt

# Dispatcher + Prefect
kubectl logs -n platform deploy/ingestion -f --tail=50
kubectl get flowruns -n prefect   # or Prefect UI

# Qdrant point count
kubectl exec -n platform deploy/workers -- curl -sf \
  -X POST http://qdrant:6333/collections/<collection>/points/count \
  -H 'Content-Type: application/json' -d '{"exact":true}'

# Cloud SQL (via proxy or authorized pod)
# SELECT logical_uri, generation, status FROM document_versions ORDER BY created_at DESC LIMIT 5;

# Idempotency: re-trigger same generation; count unchanged
# Overwrite: upload same path again; old generation points gone, new generation indexed
```

## Rollback / cleanup

- Scale dispatcher to 0; drain subscription backlog before destroy.
- Drop test documents from Qdrant collection and `rag_metadata` tables.

## Production notes

- Enforce max object size and MIME allowlist at GCS upload boundary (ingestion API in later phase).
- Size ack deadline and dispatcher timeout to p99 flow duration.
