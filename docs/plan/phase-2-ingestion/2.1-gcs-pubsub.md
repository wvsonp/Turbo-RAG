# 2.1 GCS bucket + Pub/Sub notifications

## Goal

Object uploads to GCS trigger Pub/Sub messages consumed by a **dedicated dispatcher service** (not Prefect directly). The dispatcher starts Prefect flow runs and acks messages only after successful completion. Ingestion and workers GCP service accounts gain least-privilege access to the bucket and subscription (roles deferred from [1.10](../phase-1-foundation/1.10-workload-identity.md)).

## Scope

### Terraform — `infra/modules/pubsub/`

Wire module in root `infra/main.tf` with outputs for topic/subscription names and bucket name.

**GCS bucket** (naming example: `rag-ingestion-${environment}`):

- Location: `us-central1` (regional, same as cluster)
- Uniform bucket-level access enabled
- Versioning enabled
- Public access prevention enforced
- Soft delete retention (default policy)
- CMEK: prod TODO (document in tfvars comment; not required for dev)

**Pub/Sub** (main path only — DLQ in [2.5](2.5-dlq-idempotency.md)):

| Resource | Name (dev example) | Setting | Notes |
| -------- | ------------------ | ------- | ----- |
| Topic | `ingestion-uploads` | — | GCS `OBJECT_FINALIZE` notifications |
| Subscription | `ingestion-uploads-sub` | Ack deadline `600` s | Must exceed max Prefect flow duration for dev (e.g. 10-page PDF) |
| Subscription | `ingestion-uploads-sub` | Message retention `604800s` (7 days) | — |
| Subscription | `ingestion-uploads-sub` | Retain acked messages `false` | — |
| Test subscription (optional) | `ingestion-uploads-test-sub` | Same topic, separate sub | For manual peek validation only; **never** used by dispatcher |

Increase ack deadline from 60s to **600s** so the dispatcher can extend/modify ack deadline while waiting for Prefect flow completion without premature redelivery.

**GCS notification:** `google_storage_notification` on bucket for event `OBJECT_FINALIZE` → topic `ingestion-uploads`. Payload must include `bucket`, `name`, and `generation` (default `JSON_API_V1`).

**GCS → Pub/Sub IAM:** Grant `roles/pubsub.publisher` on the topic to the GCS service account used for notifications (`service-<project-number>@gs-project-accounts.iam.gserviceaccount.com` for the bucket’s project).

### Dispatcher service (design contract — implementation in 2.3)

Deploy in `platform` namespace using existing `ingestion` KSA / `ingestion-sa-{env}` GSA.

**Responsibilities:**

1. Pull messages from `ingestion-uploads-sub` (streaming pull preferred for lease management).
2. Parse GCS notification JSON; extract `bucket`, `name`, `generation`.
3. Start Prefect flow run with parameters `{bucket, object_name, generation}`.
4. Poll Prefect flow run until terminal state (`Completed` / `Failed` / `Cancelled`).
5. **Ack** message only on `Completed`; **nack** (or let ack deadline expire) on failure so Pub/Sub retries → DLQ in [2.5](2.5-dlq-idempotency.md).
6. Extend/modify ack deadline while flow is in progress (keep deadline > remaining flow time).
7. Deduplicate in-flight runs for the same `(bucket, name, generation)` within the dispatcher process.

**Out of scope for 2.1:** Dispatcher code; Prefect flow logic ([2.3](2.3-ingestion-flow.md)).

### Terraform — WI extension in `infra/modules/iam/`

Extend the existing `local.services` map (DRY with Phase 1.10) with optional role flags or a separate `locals.ingestion_iam` block. Add **scoped** bindings (not project-wide where avoidable):

| GCP SA | KSA | Roles |
| ------ | --- | ----- |
| `ingestion-sa-{env}` | `platform/ingestion` | `roles/storage.objectViewer` on ingestion bucket; `roles/pubsub.subscriber` on `ingestion-uploads-sub` |
| `workers-sa-{env}` | `platform/workers` (flow jobs may use `prefect/workers` — see [2.2](2.2-prefect-on-gke.md)) | `roles/storage.objectViewer` on ingestion bucket; `roles/pubsub.subscriber` on `ingestion-uploads-sub`; `roles/aiplatform.user` at project level (Vertex embeddings — no narrower role for `text-embedding-004`) |

**Remove** Pub/Sub subscriber from workers if dispatcher is the sole consumer; keep on workers only if needed for replay tooling. Default: **dispatcher only** subscribes to main subscription.

Use:

- `google_storage_bucket_iam_member`
- `google_pubsub_subscription_iam_member`

Pass bucket name and subscription id from `module.pubsub` outputs into `module.iam` (or a small `module.ingestion_iam` submodule to keep `iam/main.tf` readable).

**Out of scope for 2.1:** DLQ topic, `dead_letter_policy`, Pub/Sub system SA grants ([2.5](2.5-dlq-idempotency.md)); `prefect-server-sa` ([2.2](2.2-prefect-on-gke.md)).

## Implementation notes

```hcl
# Example notification (adjust resource names to module layout)
resource "google_storage_notification" "ingestion" {
  bucket         = google_storage_bucket.ingestion.name
  payload_format = "JSON_API_V1"
  topic          = google_pubsub_topic.ingestion_uploads.id
  event_types    = ["OBJECT_FINALIZE"]
}

resource "google_pubsub_subscription" "ingestion_uploads" {
  name  = "ingestion-uploads-sub"
  topic = google_pubsub_topic.ingestion_uploads.id

  ack_deadline_seconds       = 600
  message_retention_duration = "604800s"
  retain_acked_messages      = false
}
```

After apply, confirm notification SA can publish:

```bash
gcloud pubsub topics get-iam-policy ingestion-uploads --project=turbo-rag
```

## Acceptance criteria

- [ ] Uploading a test file to the bucket publishes a message to the topic.
- [ ] Message payload includes `bucket`, `name`, and `generation`.
- [ ] Subscription `ingestion-uploads-sub` has ack deadline ≥ 600s.
- [ ] IAM: GCS notification SA has `pubsub.publisher` on topic; `ingestion-sa-{env}` has bucket viewer + subscription subscriber on main sub only.
- [ ] Resources defined in Terraform only.
- [ ] Targeted apply succeeds without enabling APIs mid-flow (prep checklist passed).
- [ ] Pod-level proof: pod using KSA `ingestion` can list bucket objects via WI (no JSON key).
- [ ] Validation does **not** consume production messages with `--auto-ack` on `ingestion-uploads-sub`.

## Validation commands

```bash
# Prep (if not done)
gcloud services enable pubsub.googleapis.com --project=turbo-rag

cd /home/wvsonp/Turbo-RAG/infra
terraform plan -var-file=environments/dev.tfvars -target=module.pubsub -target=module.iam
terraform apply -var-file=environments/dev.tfvars -target=module.pubsub -target=module.iam

# Upload → verify message published (peek only — do NOT ack production sub)
echo test > /tmp/sample.txt
gcloud storage cp /tmp/sample.txt gs://<ingestion-bucket>/incoming/sample.txt

# Safe: pull without ack (message remains for dispatcher)
gcloud pubsub subscriptions pull ingestion-uploads-sub --limit=1 --project=turbo-rag

# Or use a dedicated test subscription on the same topic (recommended)
# gcloud pubsub subscriptions pull ingestion-uploads-test-sub --auto-ack --limit=1

# Verify ack deadline
gcloud pubsub subscriptions describe ingestion-uploads-sub \
  --project=turbo-rag --format="value(ackDeadlineSeconds)"

# WI proof (kubectl 1.34+: use --overrides, not --serviceaccount)
kubectl run wi-gcs-ingestion --rm -i --restart=Never -n platform \
  --image=google/cloud-sdk:slim \
  --overrides='{"spec":{"serviceAccountName":"ingestion"}}' \
  -- gcloud storage ls gs://<ingestion-bucket>/incoming/
```

**Warning:** Never run `--auto-ack` on `ingestion-uploads-sub` once the dispatcher is deployed — it will steal messages and break end-to-end ingestion.

## Rollback / cleanup

- Stop dispatcher deployment before draining subscription.
- Remove GCS notification before deleting topic.
- Remove subscription IAM before deleting subscription.
- `terraform destroy -target=module.pubsub` after workloads stop publishing/consuming.

## Production notes

- Separate bucket per environment; no cross-env WI or bucket IAM.
- Enable CMEK and audit logs before prod traffic.
- Size ack deadline to p99 flow duration + buffer.
