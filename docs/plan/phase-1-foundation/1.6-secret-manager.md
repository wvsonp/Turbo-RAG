# 1.6 Secret Manager

## Goal

Store third-party secrets (e.g. OpenAI API key) in GCP Secret Manager and mount into pods via **CSI driver**—not Kubernetes Secret objects or plain env vars for sensitive values.

## Scope

- `infra/modules/secret_manager/`
- Secret resources + IAM for workload SAs (after [1.10](1.10-workload-identity.md))
- Helm values for Secret Manager CSI volumes

## Prerequisites

- [1.1](1.1-gcp-bootstrap.md)
- GKE cluster ([1.3](1.3-gke-cluster.md)) for CSI driver install

## Implementation notes

```hcl
resource "google_secret_manager_secret" "openai_key" {
  secret_id = "openai-api-key"
  replication { auto {} }
}
```

Install [Secret Manager CSI driver](https://github.com/GoogleCloudPlatform/secrets-store-csi-driver-provider-gcp) on cluster (Helm or addon).

Prefer Workload Identity for GCP-native APIs; Secret Manager only for keys that cannot use WI.

## Acceptance criteria

- [ ] Secret **containers** exist in Terraform (values added manually or via `gcloud`, not in git).
- [ ] CSI driver installed on cluster.
- [ ] Sample pod mounts secret as file; app reads path, not env var.
- [ ] Workload SA has `roles/secretmanager.secretAccessor` on specific secrets only.

## Validation commands

```bash
gcloud secrets list --project=turbo-rag
kubectl describe pod <test-pod>  # volume mount present
```

## Rollback / cleanup

- Disable secret versions; remove CSI volume from chart before destroy.

## Production notes

- Audit secret access logs; rotate external API keys on schedule.

## Dependencies

- [1.3](1.3-gke-cluster.md)
