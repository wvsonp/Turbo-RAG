# 2.5 DLQ + idempotency

## Goal

Failed messages land in a dead-letter topic; re-running flows does not duplicate vectors or metadata.

## Scope

- Pub/Sub DLQ subscription + max delivery attempts
- Idempotency keys (document hash + chunk id) in Qdrant upsert and DB writes

## Prerequisites

- [2.3](2.3-ingestion-flow.md)

## Acceptance criteria

- [ ] Forced failure (bad file) moves message to DLQ after N attempts.
- [ ] Re-run flow for same `document_id` does not increase point count.
- [ ] Alert or log metric for DLQ depth > 0 (wire to Phase 4 alerts optional).

## Validation commands

```bash
gcloud pubsub subscriptions describe <sub> --format="yaml(deadLetterPolicy)"
# run flow twice, compare Qdrant count
```
