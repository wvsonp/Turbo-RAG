# 1.8 Helm charts

## Goal

One Helm chart per deployable service with probes, ServiceAccount, values per environment, and lint-clean templates.

## Scope

- `helm/api/`, `helm/ingestion/`, `helm/query/`, `helm/workers/`
- `values.yaml` + `values-dev.yaml` (and `values-prod.yaml` stub)

## Prerequisites

- [1.3 GKE](1.3-gke-cluster.md) applied
- [1.7](1.7-service-skeletons.md) images in registry

## Implementation notes

```
helm/<service>/
├── Chart.yaml
├── values.yaml
├── values-dev.yaml
└── templates/
    ├── deployment.yaml
    ├── service.yaml
    ├── serviceaccount.yaml
    └── hpa.yaml          # optional stub; full HPA in Phase 6
```

Required probes on every Deployment:

```yaml
livenessProbe:
  httpGet:
    path: /health
    port: 8080
  initialDelaySeconds: 15
readinessProbe:
  httpGet:
    path: /ready
    port: 8080
  initialDelaySeconds: 10
```

**Early CI (local until Phase 5):**

```bash
helm lint helm/api
helm template api helm/api -f helm/api/values-dev.yaml
```

## Acceptance criteria

- [ ] Charts exist for api, ingestion, query, workers.
- [ ] `helm lint` passes for each chart.
- [ ] `helm upgrade --install` deploys skeleton pods to dev cluster; pods reach Ready.
- [ ] Image tag set via values (git SHA), not hardcoded `latest` in templates.
- [ ] ServiceAccount template ready for Workload Identity annotation ([1.10](1.10-workload-identity.md)).

## Validation commands

```bash
helm lint helm/api
helm upgrade --install api helm/api -f helm/api/values-dev.yaml --namespace platform --create-namespace
kubectl get pods -n platform
kubectl port-forward svc/api 8080:8080 -n platform
curl -sf localhost:8080/health
```

## Rollback / cleanup

```bash
helm uninstall api -n platform
```

## Production notes

- Resource requests/limits set per service; PodDisruptionBudget for app tier in prod.
