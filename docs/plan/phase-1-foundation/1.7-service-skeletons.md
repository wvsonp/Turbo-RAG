# 1.7 Service skeletons (Docker)

## Goal

Buildable, pushable container images for each service—**skeleton only**: `/health`, `/ready`, structured logging, and optional stub `GET /metrics` (full metrics in Phase 4).

## Scope

- `services/api/`, `services/ingestion/`, `services/query/`, `services/workers/`
- Multi-stage Dockerfiles per service
- Push to Artifact Registry ([1.4](1.4-artifact-registry.md))

## Prerequisites

- [1.4 Artifact Registry](1.4-artifact-registry.md)

## Implementation notes

**Clarification:** Phase 1 has **no RAG business logic**—only platform endpoints and wiring hooks.

```dockerfile
FROM python:3.11-slim AS builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

FROM python:3.11-slim
WORKDIR /app
COPY --from=builder /usr/local/lib/python3.11/site-packages /usr/local/lib/python3.11/site-packages
COPY . .
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8080"]
```

Each FastAPI app exposes:

- `GET /health` — liveness (process up)
- `GET /ready` — readiness (dependencies optional stub=true in dev)
- `GET /metrics` — Prometheus text format stub (counter `up 1`) optional until Phase 4

## Acceptance criteria

- [ ] All four service directories exist with Dockerfiles.
- [ ] `docker build` succeeds locally for each service.
- [ ] Images pushed to Artifact Registry with tag `:{git-sha}`.
- [ ] `/health` and `/ready` return 200 from container run locally.
- [ ] No secrets baked into images.

## Validation commands

```bash
docker build -t api:local services/api
docker run --rm -p 8080:8080 api:local
curl -sf localhost:8080/health && curl -sf localhost:8080/ready
# push
docker tag api:local us-central1-docker.pkg.dev/turbo-rag/rag-platform/api:$(git rev-parse --short HEAD)
docker push us-central1-docker.pkg.dev/turbo-rag/rag-platform/api:$(git rev-parse --short HEAD)
```
