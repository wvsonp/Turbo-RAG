# 2.5 DLQ + idempotency

## Goal

Failed Pub/Sub deliveries land in a dead-letter topic after bounded retries; re-running ingestion for the same document does not duplicate Qdrant points or metadata rows. DLQ **topology** is built here (not in [2.1](2.1-gcs-pubsub.md)); **idempotent IDs** are introduced in [2.3](2.3-ingestion-flow.md) and validated here.

## Scope

### Pub/Sub DLQ (Terraform in `infra/modules/pubsub/` or extension)

| Resource | Name (dev example) |
| -------- | ------------------ |
| DLQ topic | `ingestion-uploads-dlq` |
| DLQ subscription | `ingestion-uploads-dlq-sub` (for inspection / replay tooling) |

**Main subscription** (`ingestion-uploads-sub` from 2.1) — add:

```hcl
dead_letter_policy {
  dead_letter_topic     = google_pubsub_topic.ingestion_uploads_dlq.id
  max_delivery_attempts = 5
}
```

**Pub/Sub service agent IAM** (commonly missed; see [GCP Pub/Sub dead letter docs](https://cloud.google.com/pubsub/docs/dead-letter-topics)):

Let `pubsub_sa = "service-${data.google_project.project.number}@gcp-sa-pubsub.iam.gserviceaccount.com"`.

| Binding | Role | Resource |
| ------- | ---- | -------- |
| Forward failures to DLQ | `roles/pubsub.publisher` | DLQ topic `ingestion-uploads-dlq` |
| Redeliver / ack on primary sub | `roles/pubsub.subscriber` | Main subscription `ingestion-uploads-sub` |

Use `google_pubsub_topic_iam_member` and `google_pubsub_subscription_iam_member`.

### Idempotency validation

- Confirm [2.3](2.3-ingestion-flow.md) uses stable `point_id` / `document_id` keys.
- Forced failure path: publish or process a deliberately bad object; after 5 failed deliveries, message appears on DLQ subscription.
- Re-run flow for same `document_id`: Qdrant point count unchanged; DB row not duplicated.

### Observability (optional in dev)

- Log line or metric when DLQ depth > 0; full alert in Phase 4.

## Prerequisites

- [2.1](2.1-gcs-pubsub.md) — main topic and subscription exist
- [2.3](2.3-ingestion-flow.md) — deterministic point IDs implemented

## Acceptance criteria

- [ ] `dead_letter_policy` present on `ingestion-uploads-sub` (`max_delivery_attempts = 5`).
- [ ] Pub/Sub service agent has publisher on DLQ topic and subscriber on main subscription.
- [ ] Forced failure (bad file / poison message) moves message to DLQ after N attempts.
- [ ] DLQ message visible: `gcloud pubsub subscriptions pull ingestion-uploads-dlq-sub --auto-ack --limit=1`.
- [ ] Re-run flow for same `document_id` does not increase Qdrant point count.
- [ ] Alert or log metric for DLQ depth > 0 (optional until Phase 4).

## Validation commands

```bash
gcloud pubsub subscriptions describe ingestion-uploads-sub \
  --project=turbo-rag --format="yaml(deadLetterPolicy)"

gcloud pubsub topics get-iam-policy ingestion-uploads-dlq --project=turbo-rag

# Trigger poison message / bad file via upload + failing flow
gcloud pubsub subscriptions pull ingestion-uploads-dlq-sub \
  --project=turbo-rag --auto-ack --limit=1

# Idempotency: run flow twice for same document_id
curl -sf -X POST http://qdrant:6333/collections/<collection>/points/count \
  -H 'Content-Type: application/json' -d '{"exact":true}'
```

## Rollback / cleanup

- Remove `dead_letter_policy` before deleting DLQ topic.
- Drain DLQ subscription before destroy.

## Production notes

- Monitor DLQ depth; define replay runbook before prod.
- Consider alerting on any DLQ message in prod.
