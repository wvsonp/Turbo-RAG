# 2.1 GCS bucket + Pub/Sub notifications

## Goal

Object uploads to GCS trigger Pub/Sub messages that workers can consume. Ingestion and workers GCP service accounts gain least-privilege access to the bucket and subscription (roles deferred from [1.10](../phase-1-foundation/1.10-workload-identity.md)).

## Scope

### Terraform — `infra/modules/pubsub/`

Wire module in root `infra/main.tf` with outputs for topic/subscription names and bucket name.

**GCS bucket** (naming example: `rag-ingestion-${environment}`):

- Location: `us-central1` (regional, same as cluster)
- Uniform bucket-level access enabled
- Versioning enabled
- Public access prevention enforced
- Soft delete retention (default policy)
- CMEK: prod TODO (document in tfvars comment; not required for dev)

**Pub/Sub** (main path only — DLQ in [2.5](2.5-dlq-idempotency.md)):

| Resource | Name (dev example) |
| -------- | ------------------ |
| Topic | `ingestion-uploads` |
| Subscription | `ingestion-uploads-sub` |
| Ack deadline | `60` seconds |
| Message retention | `604800s` (7 days) |

**GCS notification:** `google_storage_notification` on bucket for event `OBJECT_FINALIZE` → topic `ingestion-uploads`.

**GCS → Pub/Sub IAM:** Grant `roles/pubsub.publisher` on the topic to the GCS service account used for notifications (`service-<project-number>@gs-project-accounts.iam.gserviceaccount.com` for the bucket’s project).

### Terraform — WI extension in `infra/modules/iam/`

Extend the existing `local.services` map (DRY with Phase 1.10) with optional role flags or a separate `locals.ingestion_iam` block. Add **scoped** bindings (not project-wide where avoidable):

| GCP SA | Roles |
| ------ | ----- |
| `ingestion-sa-{env}` | `roles/storage.objectViewer` on ingestion bucket; `roles/pubsub.subscriber` on `ingestion-uploads-sub` |
| `workers-sa-{env}` | `roles/storage.objectViewer` on ingestion bucket; `roles/pubsub.subscriber` on `ingestion-uploads-sub`; `roles/aiplatform.user` at project level (Vertex embeddings — no narrower role for `text-embedding-004`) |

Use:

- `google_storage_bucket_iam_member`
- `google_pubsub_subscription_iam_member`

Pass bucket name and subscription id from `module.pubsub` outputs into `module.iam` (or a small `module.ingestion_iam` submodule to keep `iam/main.tf` readable).

**Out of scope for 2.1:** DLQ topic, `dead_letter_policy`, Pub/Sub system SA grants ([2.5](2.5-dlq-idempotency.md)).

## Prerequisites

- Phase 1 complete ([1.10 Workload Identity](../phase-1-foundation/1.10-workload-identity.md))

## Implementation notes

```hcl
# Example notification (adjust resource names to module layout)
resource "google_storage_notification" "ingestion" {
  bucket         = google_storage_bucket.ingestion.name
  payload_format = "JSON_API_V1"
  topic          = google_pubsub_topic.ingestion_uploads.id
  event_types    = ["OBJECT_FINALIZE"]
}
```

After apply, confirm notification SA can publish:

```bash
gcloud pubsub topics get-iam-policy ingestion-uploads --project=turbo-rag
```

## Acceptance criteria

- [ ] Uploading a test file to the bucket publishes a message to the topic.
- [ ] Subscription deliverable by test subscriber (`gcloud pubsub subscriptions pull ingestion-uploads-sub`).
- [ ] IAM: GCS notification SA has `pubsub.publisher` on topic; `ingestion-sa-{env}` and `workers-sa-{env}` have bucket viewer + subscription subscriber.
- [ ] Resources defined in Terraform only.
- [ ] Targeted apply succeeds without enabling APIs mid-flow (prep checklist passed).
- [ ] Pod-level proof: pod using KSA `ingestion` can list bucket objects via WI (no JSON key).

## Validation commands

```bash
# Prep (if not done)
gcloud services enable pubsub.googleapis.com --project=turbo-rag

cd /home/wvsonp/Turbo-RAG/infra
terraform plan -var-file=environments/dev.tfvars -target=module.pubsub -target=module.iam
terraform apply -var-file=environments/dev.tfvars -target=module.pubsub -target=module.iam

# Upload → Pub/Sub
echo test > /tmp/sample.txt
gcloud storage cp /tmp/sample.txt gs://<ingestion-bucket>/incoming/sample.txt
gcloud pubsub subscriptions pull ingestion-uploads-sub --auto-ack --limit=1 --project=turbo-rag

# WI proof (kubectl 1.34+: use --overrides, not --serviceaccount)
kubectl run wi-gcs-ingestion --rm -i --restart=Never -n platform \
  --image=google/cloud-sdk:slim \
  --overrides='{"spec":{"serviceAccountName":"ingestion"}}' \
  -- gcloud storage ls gs://<ingestion-bucket>/incoming/
```

## Rollback / cleanup

- Remove GCS notification before deleting topic.
- Remove subscription IAM before deleting subscription.
- `terraform destroy -target=module.pubsub` after workloads stop publishing/consuming.

## Production notes

- Separate bucket per environment; no cross-env WI or bucket IAM.
- Enable CMEK and audit logs before prod traffic.
