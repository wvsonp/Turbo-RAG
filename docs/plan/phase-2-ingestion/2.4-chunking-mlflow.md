# 2.4 Chunking strategies + MLflow experiments

## Goal

Compare fixed-size, recursive, and semantic chunking on the same source document; log experiment params/metrics to MLflow using a **durable local file backend** suitable for Kubernetes jobs. Production MLflow server deployment is deferred to Phase [5.2](../phase-5-cicd-mlflow/5.2-mlflow-server.md).

## Scope

### Chunkers

- Three implementations behind a common interface (e.g. `Chunker` protocol or base class).
- Config-driven selection of default production chunker (document in `values` or env config).
- Chunker choice affects chunk count and Qdrant point IDs — experiments run on a **fixed test document** without writing to production collection, or use a dedicated `rag_chunks_experiments` collection.

### MLflow tracking (dev)

**Decision:** local file backend with **durable storage** — not ephemeral-only `emptyDir` as the sole accepted path.

**Required storage (choose one):**

| Option | When to use |
| ------ | ----------- |
| **PVC** (`mlruns-pvc`, e.g. 5Gi `standard-rwo`) mounted at `/mlruns` on experiment flow jobs | Preferred for in-cluster Prefect jobs |
| **Post-run copy** to GCS path `gs://<ingestion-bucket>/experiments/mlruns/` | If PVC is impractical; copy step is mandatory acceptance step |
| **Local repo path** | Only when experiments run outside cluster (workstation) |

```python
import mlflow
mlflow.set_tracking_uri("file:/mlruns")  # PVC mount path in K8s jobs
```

- Log params: `chunker`, `chunk_size`, `chunk_overlap`, `document_version_id` (test doc).
- Log metrics: `chunk_count`, `avg_chunk_length`, `flow_duration_seconds`, `embedding_batch_count`.
- Artifacts: sample chunks JSON (first N chunks) for inspection.
- Tag runs with `phase=2.4` and `environment=dev` for Phase 5.2 migration filtering.

**Explicitly out of scope for 2.4:**

- Deploying MLflow tracking server on GKE
- Wiring Cloud SQL `mlflow` database or GCS artifact root as primary store (Phase 5.2)
- Upgrading tracking URI to remote server

Phase 5.2 should import the same `mlruns/` directory layout or re-log experiments — document run IDs and PVC/GCS path in `docs/history/` when completing 2.4.

### Experiment flow design

- Separate Prefect deployment `chunking-experiment-flow` (does not consume Pub/Sub).
- Input: fixed test document URI in config (same file for all three chunkers).
- Output: three MLflow runs; no duplicate writes to production Qdrant collection.
- Default chunker selection documented in code config after comparing metrics.

## Prerequisites

- [2.3](2.3-ingestion-flow.md) — base ingestion flow works
- Vertex / Qdrant access from workers ([2.1](2.1-gcs-pubsub.md), [2.3](2.3-ingestion-flow.md))

## Acceptance criteria

- [ ] Same source document processed with all three chunking strategies.
- [ ] Three MLflow runs visible under durable `mlruns/` (PVC or GCS copy — survives pod termination).
- [ ] Each run has distinct params (`chunker=...`) and metrics (chunk count, avg length, duration).
- [ ] Default production chunker selected and documented in code config.
- [ ] `mlruns/` directory readable after flow job pod exits (prove by listing from PVC or GCS).
- [ ] Format suitable for migration to Phase 5.2 server later.

## Validation commands

```bash
# After experiment flow runs (in-cluster)
kubectl exec -n prefect <experiment-job-pod> -- ls -la /mlruns/
# Or if using PVC:
kubectl exec -n prefect deploy/<prefect-worker-with-pvc> -- ls -la /mlruns/

# Or after GCS copy:
gcloud storage ls gs://<ingestion-bucket>/experiments/mlruns/

# Local inspection (copy mlruns from PVC/GCS first if needed)
mlflow ui --backend-store-uri file:./mlruns --port 5000
# Browser: three runs with different chunker param
```

## Rollback / cleanup

- Delete experiment MLflow runs from PVC or GCS path; no server teardown.
- Remove `rag_chunks_experiments` collection if created.

## Production notes

- Before prod, switch tracking URI to managed MLflow ([5.2](../phase-5-cicd-mlflow/5.2-mlflow-server.md)) and retire file-only tracking.
- Do not run chunking experiments against prod collection.
