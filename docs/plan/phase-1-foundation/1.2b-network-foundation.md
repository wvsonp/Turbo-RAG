# 1.2b Network foundation (VPC)

## Goal

VPC, subnets, Private Service Access, and egress (Cloud NAT) so GKE and Cloud SQL can use **private IPs only**—required before production-shaped Cloud SQL and private GKE.

## Scope

- VPC with regional subnets for GKE nodes and pods (alias IP ranges if using VPC-native cluster).
- Private Service Access (allocated range + `servicenetworking` connection) for Cloud SQL.
- Cloud Router + Cloud NAT for controlled egress from private nodes.
- Firewall rules: deny broad ingress; allow health checks and internal service traffic as needed.

## Prerequisites

- [1.2 Terraform layout](1.2-terraform-layout.md)
- API `compute.googleapis.com`, `servicenetworking.googleapis.com` enabled

## Implementation notes

Add `infra/modules/network/` (or inline in root) with:

- `google_compute_network` (custom mode, no auto subnets)
- Subnets per region with secondary ranges for pods/services if GKE is VPC-native
- `google_compute_global_address` + `google_service_networking_connection` for PSA
- `google_compute_router` + `google_compute_router_nat`

Wire GKE module to use this VPC/subnet (update [1.3](1.3-gke-cluster.md) module inputs).

**Dev shortcut (acceptable temporarily):** Public GKE endpoint + Cloud SQL public IP disabled but without full NAT—**not** acceptable for prod checklist.

## Acceptance criteria

- [ ] VPC and subnets exist in Terraform and `terraform plan` is clean.
- [ ] PSA connection active; reserved peering range visible for Cloud SQL.
- [ ] Cloud NAT configured if nodes have no public IPs.
- [ ] GKE module variables reference VPC/subnet (even if cluster not applied yet).
- [ ] Documented CIDR plan in module README or `docs/history/IaC.md` (no overlap between pod/service/node/PSA ranges).

## Validation commands

```bash
cd infra
terraform plan -var-file=environments/dev.tfvars -target=module.network  # when module exists
gcloud compute networks list --project=turbo-rag
gcloud compute addresses list --global --filter="purpose=VPC_PEERING"
```

## Rollback / cleanup

- Destroy order: GKE → Cloud SQL → PSA connection → NAT → subnets → VPC.

## Production notes

- Private GKE control plane endpoint optional for prod; document access (bastion / IAP / VPN).
- Enable VPC Flow Logs on prod subnets.

## Dependencies

- [1.2](1.2-terraform-layout.md)
- Blocks [1.5 Cloud SQL](1.5-cloudsql.md) private IP and recommended before [1.3](1.3-gke-cluster.md) apply if moving to private cluster.
