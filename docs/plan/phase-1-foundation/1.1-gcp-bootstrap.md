# 1.1 GCP project bootstrap

## Goal

Create the GCP project, enable required APIs, remote state bucket, and a **temporary** bootstrap identity for Terraform—without baking long-lived broad keys into the long-term design.

## Scope

- One GCP project per environment target (start with **dev** project `turbo-rag`; add prod project or separate state prefix before prod apply).
- APIs, state bucket, bootstrap SA.
- Document migration path to GitHub OIDC / Workload Identity Federation for CI.

## Prerequisites

- GCP billing account and org permissions to create projects (or use existing project).
- `gcloud` CLI installed locally.

## Implementation notes

**APIs to enable** (also codify in Terraform via `google_project_service`):

- `container.googleapis.com`
- `sqladmin.googleapis.com`
- `pubsub.googleapis.com`
- `artifactregistry.googleapis.com`
- `secretmanager.googleapis.com`
- `storage.googleapis.com`
- `aiplatform.googleapis.com`
- `servicenetworking.googleapis.com` (Cloud SQL private IP)
- `compute.googleapis.com` (VPC)

**Remote state:** `gs://rag-platform-tf-state` with versioning and uniform bucket-level access.

**Bootstrap SA (temporary):** Prefer **narrow** roles over project `Editor`:

| Purpose | Suggested roles (bootstrap only) |
| ------- | -------------------------------- |
| Terraform apply (dev) | `roles/editor` *or* split: `container.admin`, `compute.networkAdmin`, `iam.serviceAccountAdmin`, `storage.admin`, `cloudsql.admin`, `secretmanager.admin`, `artifactregistry.admin`, `pubsub.admin` |
| State bucket | `roles/storage.objectAdmin` on state bucket only |

**Do not** commit JSON keys to the repo. Store locally or in GitHub encrypted secrets until OIDC is wired (Phase 5).

**Target CI auth (Phase 5):** GitHub Actions → Workload Identity Federation → GCP SA with same narrow roles as Terraform apply SA.

## Acceptance criteria

- [ ] GCP project exists (`turbo-rag` or documented name).
- [ ] Required APIs enabled and visible in Console / `gcloud services list --enabled`.
- [ ] GCS state bucket exists with versioning enabled.
- [ ] Bootstrap SA can run `terraform plan` against dev (manual test).
- [ ] No service account JSON keys in git; bootstrap key rotation date noted in `docs/history/IaC.md` if a key was created.

## Validation commands

```bash
gcloud config get-value project
gcloud services list --enabled --project=turbo-rag
gsutil versioning get gs://rag-platform-tf-state
```

## Rollback / cleanup

- Disable APIs only if tearing down entire project.
- Delete bootstrap SA keys after OIDC migration; disable unused keys immediately.

## Production notes

- Use **separate** GCP projects for dev and prod, or separate state prefixes + distinct tfvars—never share one state file across environments.
- Prod bootstrap: same pattern, stricter IAM; no `Editor` on prod long-term.

## Dependencies

None (first step).
