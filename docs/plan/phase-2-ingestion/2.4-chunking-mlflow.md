# 2.4 Chunking strategies + MLflow experiments

## Goal

Compare fixed-size, recursive, and semantic chunking on the same source document; log experiment params/metrics to MLflow using the **simplest dev setup** (local file backend). Production MLflow server deployment is deferred to Phase [5.2](../phase-5-cicd-mlflow/5.2-mlflow-server.md).

## Scope

### Chunkers

- Three implementations behind a common interface (e.g. `Chunker` protocol or base class).
- Config-driven selection of default production chunker (document in `values` or env config).

### MLflow tracking (dev)

**Decision:** use a **local file backend** only in this step — gradual learning path; no GKE MLflow server required.

```python
import mlflow
mlflow.set_tracking_uri("file:./mlruns")  # or file:/path/on/emptyDir
```

- Store runs under `mlruns/` (emptyDir volume on worker job, or path under flow working directory).
- Log params: chunker name, chunk size / overlap (if applicable).
- Log metrics: chunk count, avg chunk length, flow duration.
- Artifacts optional (sample chunks JSON) for inspection.

**Explicitly out of scope for 2.4:**

- Deploying MLflow tracking server on GKE
- Wiring Cloud SQL `mlflow` database or GCS artifact root (Phase 5.2)
- Upgrading tracking URI to remote server

Phase 5.2 should be able to import or attach to the same `mlruns/` layout or re-log experiments — document run IDs in flow README when completing 2.4.

## Prerequisites

- [2.3](2.3-ingestion-flow.md) — base ingestion flow works
- Vertex / Qdrant access from workers ([2.1](2.1-gcs-pubsub.md), [2.3](2.3-ingestion-flow.md))

## Acceptance criteria

- [ ] Same source document processed with all three chunking strategies.
- [ ] Three MLflow runs visible under local `mlruns/` (inspect via `mlflow ui --backend-store-uri file:./mlruns` on a machine with the directory, or list `mlruns/` structure).
- [ ] Each run has distinct params (`chunker=...`) and metrics (chunk count, avg length, duration).
- [ ] Default production chunker selected and documented in code config.
- [ ] `mlruns/` artifacts directory present and readable; format suitable for migration to Phase 5.2 server later.

## Validation commands

```bash
# From repo or copied mlruns dir
ls -la mlruns/
mlflow ui --backend-store-uri file:./mlruns --port 5000
# Browser: three runs with different chunker param
```

## Rollback / cleanup

- Delete `mlruns/` local dir; no server teardown.

## Production notes

- Before prod, switch tracking URI to managed MLflow ([5.2](../phase-5-cicd-mlflow/5.2-mlflow-server.md)) and retire file-only tracking.
